Solution Architecture - Reference Diagram

Collaborative-Filtering Retrieval Pipeline

The current steel thread: a pure-CF retrieval stage (ALS, benchmarked against a popularity floor) evaluated on MovieLens 100k under a structural cold-item split, isolating the effect an item's own accumulating history has on retrieval quality by fold-in (recalculate_item) rather than retraining - user preferences are fit once and held completely constant throughout. Two warm-up curves are built from this same fold-in mechanism: one from the standard user-to-item perspective, one from the transposed item-to-user (targeted-marketing) perspective. Built for comparing against interventions later on.

Step 4 - split, in two independent parts
4.1
Cold-Item Split Shared / Generic

A fixed population of items plays the role of "cold" throughout this notebook. Eligibility: only items with at least 25 total interactions qualify - this guarantees every candidate can supply a full k=0..20 reveal sweep without running out of history partway through. Selection: 10% of the eligible population is sampled uniformly at random (no stratification by popularity tier). Reveal and reserve, per cold item: sort its interactions chronologically; the first 20 are the revealable pool (exactly k of these are treated as known history at reveal level k); everything after position 20 is permanently reserved for evaluation, unchanged at every k. This keeps the evaluated population perfectly stable across the whole sweep - only the amount of revealed history changes. This same reveal mechanism is called repeatedly by stages 8 and 9. The plain-random draw turned out to make no promise about how homogeneous the resulting population's difficulty would be - reserved-test-user counts range from 5 to 487 across these 87 items, which stage 9 has to account for directly.

4.2
Reference Set Shared / Generic

Independent, not a fold-in. A plain random 80/20 split on the warm items only (everything 4.1 did not select as cold) - no reveal levels, no fold-in, no sweep. It's a reference, not a comparison: it exists purely to answer "what does normal performance look like" for stages 6/7/8 to be read against, so plotting a warm-up curve for an already-warm item would answer no question worth asking here.

5a
Popularity Baseline Shared / Generic

Ranks items by raw training-interaction count - the same global list for every user, personalized only by excluding each user's already-seen items. No factors, no training loop, no hyperparameters, no notion of individual user preference at all - exactly why it's the right floor for this comparison. Built identically regardless of which algorithm occupies 5b; exists to answer "is 5b earning its complexity." Also the conceptual template for stage 9's user-activity floor - "rank by observed volume, no personalization" applied to the opposite axis.

5b
Collaborative Filtering - ALS Algorithm-Specific

Learns latent user/item factor vectors by alternately solving, in closed form, for all user factors with item factors fixed, then all item factors with user factors fixed. The reason ALS - not BPR - is the algorithm here: that alternating structure gives recalculate_item(itemid, item_users) natively - an exact closed-form solve for one item's factor, holding every user's factor completely untouched. BPR's joint stochastic optimization has no equivalently clean "hold one side fixed" operation, so a full retrain would let user factors drift along with the item's, confounding the exact thing this experiment isolates. The primary swap point in this diagram for future interventions (content embeddings, a content-blended model, LLM-simulated interactions).

6
Warm-Item Reference Score Diagnostic / Benchmark

Computed ahead of stage 7's cold-start evaluation, on purpose: reading stage 7's near-zero numbers with no frame of reference tells you little. Both models are evaluated on 4.2's held-out split, using each model's own natively-fit representations - no fold-in involved, that mechanism exists specifically for the cold-item sweeps. Fit here as N_SEEDS=10 independent ALS fits (factor initialization is random), reporting mean ± spread; these exact same 10 fits are reused, unchanged, by stages 7, 8, and 9, so every downstream stage rests on the same underlying models rather than independently-drawn samples. This is also where the shared evaluation helpers get defined, including AUC - a full-catalog pairwise ranking metric (Mann-Whitney rank-sum form) that needs no K at all, included specifically because every other metric here needed a debatable choice of K.

7
Cold Start Retrieval Evaluation Diagnostic / Benchmark

Every reserved test interaction (stage 4.1) belongs to a cold item, evaluated at reveal level k=0 - no history revealed at all. For 5b, this has an exact, provable answer, verified computationally rather than merely observed to be small: with zero observed interactions, recalculate_item's regularized closed-form solve collapses to the exact zero vector, every time, for every seed - a zero vector's dot product with any user factor is exactly zero, so the item cannot outrank anything on NDCG/Recall/HitRate@100, all exactly 0.0000. Popularity's k=0 failure is a separate, structural guarantee: a cold item's training-interaction count is exactly zero, so it can never appear in a popularity ordering regardless of training dynamics. AUC is the exception - a zero-factor item still lands somewhere in the full-catalog ranking, just slightly below chance (0.4213, not 0.5000), since the median real item score sits just above zero. Read alongside stage 6's reference score, computed just before this.

8
Warm-Up Curve - User-to-Item (Mode A) Diagnostic / Benchmark

The standard consumer-facing question: for a given user, does a cold item surface in their top-K as it accumulates its own history? Built by fold-in, not retraining. For each k in the 0..20 sweep, computes 5b's fold-in factor for every cold item using exactly the first k of its own revealed interactions via recalculate_item, evaluates against the same fixed reserved test set throughout, and repeats this across the 10 models fit in stage 6 - it does not refit or re-invoke stage 5 at any point on the curve. K=100, not a stricter cutoff: a cold item competing against ~1,600 fully-trained warm items for one of only 10 slots never wins that competition anywhere in the sweep, for any user - the resulting curve is a flat, uninformative zero end to end at K=10. At K=100 a real, growing signal appears on NDCG/Recall/HitRate. AUC (no K) adds a subtler read: ALS stays ahead of Popularity throughout, but the gap shrinks from 0.39 at k=0 to 0.12 at k=20, not widens - Popularity's climb from an extreme structural disadvantage closes distance faster in relative terms than ALS's climb, which is real but flattening.

k=20 HitRate@100 - Pop 0.0000 / ALS 0.1071 (mean of 10)k=20 AUC - Pop 0.5339 / ALS 0.6495 (gap 0.12, down from 0.39 at k=0)
9
Warm-Up Curve - Item-to-User (Mode B) Diagnostic / Benchmark

The targeted-marketing question, the transposed dual of stage 8: for a single cold item, rank users by predicted affinity, and check whether the users known (from the reserved test set) to actually want it land near the top of its top-K. Same fold-in factors as 8, same frozen-user-factor principle, just the ranking axis transposed - no new fitting. 5a has no meaningful version of this (no per-user signal to rank users by, only a tie), so it's compared against its direct dual instead: a frozen global-user-activity ranking (each user's total interaction count in 4.2's train split). Uses its own K_MODE_B=10, not stage 6's K=100, since ~940 candidate users is a much smaller pool than ~1,600 items and a large K there saturates HitRate for both models alike. Precision@K is reported alongside Recall@K since the two are capped in opposite directions by each item's reserved-test-user count r_i (5 to 487) - a real cross-item comparability problem NDCG@K and AUC don't have. The Downsampled Test Set (a fixed, random 5-user sample per item - every eligible item is guaranteed at least 5 by construction, MIN_INTERACTIONS(25) - N_REVEAL(20) = 5) fixes that comparability problem for NDCG/Precision/Recall/HitRate; AUC keeps the full reserved test set throughout, since its ceiling is trivially 1.0 regardless of r_i. The two populations tell genuinely different stories: on the fairness-controlled downsampled metrics, 5b overtakes the activity floor around k≈11-15; on the full-population AUC, 5b still trails at k=20 - localizing the remaining gap to the high-r_i, near-popular items specifically, not the cold-item population as a whole.

Extension points - deferred, not built

Confidence-Weighted Interactions extends → 3

confidence = 1 + α·rating (Hu et al. 2008). ALS reads interaction magnitude natively, so this would be a direct extension of the current interaction matrix - not used here, every interaction counts equally regardless of rating.

Positive-Only Filtering extends → 3

Exclude low ratings (e.g. <3 stars) from the interaction set entirely, rather than including them at low weight. Addresses "1-star ≠ dislike."

Time-Based Split extends → 4.1

Not the same thing as stage 4.1's chronological reveal - that orders each cold item's own interactions internally, but every warm item still trains on 100% of its history regardless of date. A true time-based split would draw one global cutoff T across the whole dataset (train on everything before T, test after), so "cold" means "didn't exist in the catalog yet," not "deliberately withheld." A realism upgrade, not a correctness fix - stage 4.1 already guarantees structural coldness without it.

Content Embeddings + LLM-Simulated Interactions extends → 1, 5b

How content embeddings, improved content embeddings, and LLM-simulated interactions enter this same fold-in mechanism is an open design question - not yet designed. 5a stays as-is: the floor doesn't change just because the item representation being measured against it does.

Cold-Item Selection Ceiling extends → 4.1

The r_i skew (5 to 487 reserved users/item) that motivated stage 9's Downsampled Test Set was discovered via diagnostics, not designed around at selection time. A symmetric MAX_INTERACTIONS ceiling alongside the existing floor - narrowing the eligible population itself rather than fixing it downstream - was considered and not yet implemented; the Downsampled Test Set is a complementary fix for the K-based metrics, not a substitute for addressing the underlying population choice.

Cold-User Split extends → 4.1, 8

The row-based mirror of stages 4.1 and 8 together - the same eligibility-filter-then-random-sample selection over users instead of items, entire users held out, then the same chronological-reveal-plus-fold-in treatment to build a true user warm-up curve. A related but distinct cold-start problem; the machinery to build it now already exists, just needs pointing at the other axis.
